# Sonic Animation Viewer PRD

## 1. 문서 개요

- 제품명: Sonic Animation Viewer
- 대상 파일: `sonic_animation_viewer.py`
- 대상 에셋: `sonic-sprite.png` (스프라이트 시트, 399 x 525 px)
- 실행 환경: Python, Pico2D
- 문서 상태: 구현 전 개발 요구사항

## 2. 제품 설명

LEC09에 있는 Sonic 스프라이트 시트에서 실제 캐릭터 애니메이션 프레임을 분리하고, 각 동작을 순서대로 재생하는 데스크톱 뷰어를 만든다. 별도 프로젝트 구조 없이 하나의 파이썬 파일로 구현하며, 모든 동작의 재생이 끝나면 처음 동작부터 다시 재생한다.

## 3. 목표와 제외 범위

### 목표

- 스프라이트 시트에 있는 Sonic의 애니메이션 동작을 빠짐없이 순차 재생한다.
- 동작마다 애니메이션을 5회 완주하고 다음 동작으로 넘어가기 전에 1초 대기한다.
- 프레임마다 원본 이미지에 맞는 잘라내기 영역을 사용해 배경이나 인접 프레임이 섞이지 않게 한다.
- 기존 20% 면적 기준 표시 크기에서 가로와 세로를 각각 절반으로 줄여, 프레임 표시 사각형이 캔버스 면적의 약 5%를 차지하도록 한다.
- 사용자가 종료 요청을 하면 창과 이미지 자원을 정상적으로 정리한다.

### 제외 범위

- 게임 플레이, 캐릭터 이동, 충돌, 점수, 사운드, 메뉴 및 설정 화면
- 스프라이트 시트 자체의 편집이나 자동 이미지 인식
- 별도 모듈, 이미지 에셋, 설정 파일, 테스트 파일의 추가

## 4. 사용자 시나리오

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 프로그램이 LEC09의 `sonic-sprite.png`를 불러오고 뷰어 창을 연다.
3. Sonic의 첫 동작이 프레임 순서대로 재생된다.
4. 해당 동작을 5회 완주하면 1초 대기한 뒤 다음 동작을 재생한다.
5. 마지막 동작 이후에도 1초 대기하고 첫 동작부터 전체 순서를 반복한다.
6. 사용자가 창 닫기 또는 ESC 키를 입력하면 프로그램이 종료된다.

## 5. 기능 요구사항

### FR-1. 실행 및 에셋 로드

- Python과 Pico2D를 사용한다.
- 실행 진입점은 단일 파일 `sonic_animation_viewer.py`로 한다.
- 스프라이트 시트는 대상 스크립트와 같은 `LEC09` 폴더의 `sonic-sprite.png`를 사용한다.
- 에셋 경로는 현재 작업 디렉터리에 의존하지 않도록 스크립트 위치 기준으로 결정한다.
- 이미지 로드에 실패하면 경로와 원인을 확인할 수 있는 오류를 출력하고 정상적인 오류 종료를 한다.

### FR-2. 애니메이션 데이터

- 애니메이션 동작은 이름과 프레임 영역 목록을 한 파일 안에서 명시적으로 관리한다.
- 프레임 영역은 Pico2D가 요구하는 좌표계와 원본 이미지 경계에 맞춘다.
- 행별로 프레임 간격과 크기가 다를 수 있으므로, 시트가 균일한 격자라고 가정하지 않는다.
- 재생 대상은 시트에 그려진 Sonic의 실제 동작 프레임으로 한정한다. 제목, 안내 문구, 출처 표기, 장식용 공, 다른 캐릭터 등은 애니메이션에 포함하지 않는다.
- 구현 전 프레임 좌표를 육안으로 확인하여 각 프레임에 잘림이나 이웃 이미지 포함이 없는지 검증한다.

### FR-3. 재생 순서와 반복

- 동작 목록은 코드에 선언된 순서대로 재생한다.
- 한 동작은 그 동작의 모든 프레임을 순서대로 재생하는 것을 1회로 하여 정확히 5회 완주한다.
- 5회 완주 후 다음 동작의 첫 프레임을 표시하기 전에 1초 대기한다.
- 마지막 동작에서 첫 동작으로 돌아갈 때도 동작 전환으로 취급해 1초 대기한다.
- 전체 동작 목록을 끝까지 재생한 뒤 같은 순서로 무한 반복한다.
- 프레임 간격은 기본 0.1초로 한다. 이는 인접 수업 예제와의 일관성을 위한 기본값이며, 한 파일 안의 상수로 조절 가능하게 한다.

### FR-4. 렌더링

- 캔버스 기본 크기는 1200 x 800 px로 한다.
- 각 프레임을 원본 비율 그대로 확대 또는 축소한다.
- 기존 20% 면적 기준 표시 크기의 가로와 세로를 각각 절반으로 표시한다. 이에 따라 프레임 표시 사각형의 면적은 캔버스 면적의 약 5%가 된다. 프레임 비율을 보존하며 캔버스 경계를 넘지 않도록 최종 표시 크기를 제한한다.
- 스프라이트는 캔버스 중앙에 표시하고, 프레임이 바뀌어도 기준 위치가 불필요하게 흔들리지 않도록 한다.
- 매 화면 갱신 때 현재 프레임을 그린 후 Pico2D 캔버스를 갱신한다.

### FR-5. 이벤트와 종료

- 창 닫기 이벤트와 ESC 키를 종료 입력으로 처리한다.
- 종료 시 반복 재생 루프를 빠져나오고 캔버스를 닫는다.

## 6. 비기능 요구사항

- 요구된 구현 코드는 `sonic_animation_viewer.py` 한 파일에 둔다.
- 코드와 이미지 에셋은 상대 경로로 연결하며 사용자별 절대 경로를 하드코딩하지 않는다.
- 애니메이션 데이터, 재생 상태, 프레임 진행, 그리기, 종료 처리가 읽기 쉬운 이름과 작은 함수로 구분되어야 한다.
- 재생 루프는 Pico2D 이벤트를 계속 처리하여 창 닫기 입력에 응답해야 한다.
- 프레임 좌표와 동작별 프레임 수는 수정하기 쉬운 데이터 구조로 모아 둔다.

## 7. 기본 가정 및 결정 사항

- 크기 축소 전 기준은 프레임 표시 사각형의 면적이 캔버스 면적의 20%가 되도록 계산하고, 최종 렌더링에서는 너비와 높이를 각각 절반으로 줄인다. 최종 표시 면적은 캔버스 면적의 약 5%다.
- 동작별 재생 순서는 시트에서 식별한 위에서 아래 방향의 자연스러운 순서를 기본으로 하며, 실제 분류 후 코드의 애니메이션 목록에 명시한다.
- 기본 창 크기는 1200 x 800 px로 한다. 프레임 간격 0.1초는 초안에 명시되지 않은 값에 대한 기본안이며, 수업 요구나 실행 결과와 맞지 않으면 구현 전에 조정한다.
- 스프라이트 시트의 배치가 불규칙하므로 동작 수와 각 동작의 프레임 좌표는 이미지 분석 후 확정한다. 이 문서는 검증되지 않은 프레임 수나 좌표를 미리 단정하지 않는다.

## 8. 완료 및 검수 기준

- [ ] `sonic_animation_viewer.py` 단일 파일로 실행할 수 있다.
- [ ] 프로젝트의 LEC09 폴더 밖에서 실행해도 같은 폴더의 `sonic-sprite.png`를 찾는다.
- [ ] 구현에 선언된 모든 Sonic 동작이 재생되며, 비애니메이션 문구·장식·다른 캐릭터는 프레임으로 나타나지 않는다.
- [ ] 모든 프레임에서 Sonic이 잘리지 않고 주변 프레임이나 이미지가 섞이지 않는다.
- [ ] 각 동작이 정확히 5회 완주한 뒤에만 다음 동작으로 넘어간다.
- [ ] 동작 전환마다 1초 대기가 적용되며 마지막 동작과 첫 동작 사이에도 적용된다.
- [ ] 프레임 비율을 유지하고 기존 20% 기준 표시 크기의 절반(캔버스 면적 약 5%)으로 표시하며 캔버스 밖으로 나가지 않는다.
- [ ] 창 닫기와 ESC 키로 종료할 수 있고 캔버스가 정상적으로 닫힌다.
- [ ] 이미지 파일이 없거나 로드할 수 없을 때 원인을 파악할 수 있는 메시지를 남긴다.

## 9. 단계별 구현 및 커밋 계획

각 단계는 직전 상태에서 실행 가능한 코드를 유지하는 작은 변경으로 진행한다. 아래 20단계는 구현 진행용 커밋 단위 계획이며, 이 PRD 작성 자체가 커밋을 생성하는 것은 아니다.

- 모든 커밋 메시지의 제목과 본문은 한글로 작성한다. 파일명, 라이브러리명, 코드 식별자 등 고유 명칭은 원문 표기를 허용한다.

1. `sonic_animation_viewer.py` 파일과 기본 실행 진입점을 만든다.
2. Pico2D import와 창 열기·닫기 최소 동작을 추가한다.
3. 캔버스 크기를 상수로 분리한다.
4. 스크립트 위치 기준으로 에셋 경로를 계산한다.
5. 스프라이트 시트 로드와 로드 실패 메시지를 추가한다.
6. 한 프레임을 지정 좌표로 잘라 그리는 최소 동작을 추가한다.
7. 프레임 데이터 표현 형식을 정하고 첫 동작의 프레임을 등록한다.
8. 첫 동작의 모든 프레임 좌표를 등록하고 시각적으로 확인한다.
9. 나머지 동작 그룹의 프레임 좌표를 등록한다.
10. 애니메이션 이름과 프레임 목록을 하나의 순서 있는 데이터 구조로 정리한다.
11. 현재 동작 인덱스와 프레임 인덱스 상태를 추가한다.
12. 설정 가능한 기본 프레임 간격과 프레임 진행을 구현한다.
13. 한 동작의 마지막 프레임에서 처음 프레임으로 이어지게 한다.
14. 동작 완료 횟수를 세어 5회 반복을 구현한다.
15. 5회 완료 후 다음 동작으로 이동하게 한다.
16. 동작 사이 1초 대기를 추가하고 마지막에서 처음으로 돌아갈 때도 확인한다.
17. 원본 비율을 유지하면서 기존 20% 기준 표시 크기의 절반을 계산한다.
18. 스프라이트를 캔버스 중앙에 고정하고 캔버스 경계 내 표시를 확인한다.
19. 창 닫기와 ESC 입력 처리, 종료 시 캔버스 정리를 추가한다.
20. 에셋 경로, 모든 동작, 반복 횟수, 전환 대기, 크기, 종료 동작을 통합 검수하고 최종 정리한다.

## 10. 검증 시나리오

- LEC09 외의 작업 디렉터리에서 프로그램을 실행해 에셋 경로가 정상적으로 해석되는지 확인한다.
- 애니메이션 목록을 순회하며 선언된 각 동작이 5회 재생된 뒤 다음 동작으로 이동하는지 확인한다.
- 마지막 동작 완료 후 1초 대기 뒤 첫 동작으로 이어지는지 확인한다.
- 프레임 좌표를 동작별로 재생해 잘림, 정렬 오류, 시트 내 다른 요소 혼입이 없는지 확인한다.
- 창 닫기 버튼과 ESC 키를 각각 입력해 프로그램이 정상 종료되는지 확인한다.
- 스프라이트 시트를 찾을 수 없게 한 실행에서 이해 가능한 오류 메시지가 출력되는지 확인한다.
